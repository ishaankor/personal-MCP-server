3. **For current job or NVIDIA work**: Use `get_current_job_and_nvidia_experience`
4. **For music / what is Ishaan listening to**: Use `get_current_music` or `get_spotify_telemetry`
5. **For Apple Shortcuts / automations**: Use `get_apple_shortcuts`
6. **For EDAs / research studies**: Use `get_eda_research` (dynamic multi-repo discovery)
7. **For personal website overview & chapters**: Use `get_personal_website_info` or `get_website_chapter`
8. **For all project listings**: Use `list_projects`
9. **For specific project details, creation date, timeline, stack, or README**: Use `get_project_details(project_name=...)` (e.g. Daily Motivation, Datafy, RigScouter-AI, Transformi, NotesTaker)

   - **Ordinal commits (first, second, second to last)**: Git streams are reverse-chronological (index 0 is newest). Clearly distinguish whether referring to 2nd newest vs 2nd chronologically from start of timeframe. Commit #2 and commit #N-1 can never be the same commit when total commits N > 3. State total commit count N.

    - Decompose into distinct date lookups rather than combining into an invalid single date range.
    - Always pass clean `YYYY-MM-DD` strings without timestamp suffixes.

      - If no year is specified in the prompt (e.g. "how many commits did he make from his birthday and a week after?", "what did he do on Christmas?"), ALWAYS resolve strictly to the most recent single year occurrence (e.g. 2026 for April 19 – 26, 2026).
